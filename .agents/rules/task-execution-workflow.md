# 任务执行与多问题处理工作流 (Task & TODO Execution Workflow)

## 1. 多问题/多需求拆解与 TODO 规划
- 当用户单次对话中指出多个问题、缺陷或提出多个修改需求时，**严禁一次性批量全部修改**；
- 必须首先按照优先级、模块类型或逻辑依赖，将用户需求结构化拆解为有序的 **TODO 清单**；
- 明确告知用户本次的任务规划与执行顺序，确认后按序推进。

## 2. 单一 TODO 聚焦执行 (Single-TODO Execution)
- **单步迭代**：每次修改时**只聚焦并修改当前处于激活状态的单一 TODO**；
- 严禁在当前步骤中跨 TODO 提前修改其他需求，确保每一次变更的范围绝对清晰、可控、易回滚与易测试。

## 3. 标准化三段式交付汇报
每次完成当前 TODO 的代码修改并重启 DMS 后，必须按照以下标准格式向用户汇报：
1. **🛠️ 修改了哪些**：清晰列出修改的文件路径、函数/组件及核心改动点；
2. **🎯 达到了怎样的效果**：详细说明该改动解决的具体现象及修改前后的行为对比；
3. **🔍 您该如何检验**：提供明确、具体、可操作的复现验证与测试步骤（如点击哪里、输入什么、观察什么指标）。

## 4. 提醒验证与 Git 提交流程
- **严禁自动提交**：汇报完毕后，提醒用户按照检验步骤进行本地实际体验与验证；
- **提示 Git 提交**：提醒用户“如经检验确认无误，可指示执行 Git 提交（将按 SemVer 自动递增版本并原子化提交）”；
- **用户确认后再前进**：必须在用户确认当前 TODO 验证通过（并根据用户意愿完成或跳过提交）后，方可进入下一个 TODO，循环往复直至所有需求全部完成。
